## Advisories (non-blocking, do not gate M2-1)
A1 — src/app/products/[slug]/page.tsx:57-67 — the F2 guarantee is
compile-time only; there is no runtime/HTTP assertion that the detail
page's RSC payload lacks the raw inventory numbers. TypeScript's
excess-property check protects the current field-by-field literal, but it
does NOT apply to spread properties, so a future refactor to
`map((v): ClientVariant => ({ ...v }))` would compile cleanly and
silently re-leak onHand/reserved/safetyBuffer. Cheap hardening for a
later item: in tests/test12-catalog-pages.test.ts, fetch a detail page
and assert the response body does not contain that variant's raw onHand
value (with the inventory row first set to a distinctive number so the
match cannot be coincidental).
A2 — src/lib/productService.ts:69-75 vs :133 — the comment states the
echoed `page` "reflects the caller's requested page" while only `skip` is
clamped, but line 133 returns `page: safePage`, so the echoed value is
clamped too. No behavioural impact (the listing page renders its own
locally-parsed page value, products/page.tsx:107, and ignores the
returned one) and no security impact; the comment should be corrected so
a future editor doesn't rely on the stated-but-false contract.
